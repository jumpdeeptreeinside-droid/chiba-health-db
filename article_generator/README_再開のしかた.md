# 週次記事の自動生成 — 止めた理由と、再開のしかた

**2026-08-16、週次スケジュールを止めました（削除ではなく無効化）。**

---

## 何が起きていたか

千葉県の二次医療圏シリーズは **Vol.1–10 で完結しました**（`vol_state.json` の `completed_vols` がその記録）。
それでも週次 cron は回り続け、存在しない **Vol.11** を作ろうとして毎週こう落ちていました。

```
[ERROR] Vol.11 のスケジュールが vol_state.json に未登録です
cp: cannot stat 'output/': No such file or directory
```

2026-07-19 / 07-26 / 08-02 / 08-09 の4回連続。**壊れていたのではなく、出し切っていました。**

## なぜ止めたか（撤退ではありません）

> 決まっていないものを毎週失敗させ続けると、**失敗メールがノイズになる。そしてノイズは本物の失敗を隠す。**
> 2026-08-15〜16 に `crosshealthjp` の deploy が **16回連続で失敗しても丸1日誰も気づかなかった**のは、まさにこの構造でした。

**止めるのは、次の失敗に気づける状態を保つためです。**

---

## 🔑 再開のしかた（この順番で）

### 1. まず次の号を予定表に足す

`article_generator/vol_state.json` の `vol_schedule` に、次に出す号を追加します。

```json
"vol_schedule": {
  "11": { "region": "◯◯", "note": "その号で何を言うか" }
}
```

⚠️ **これを飛ばして cron だけ戻すと、また毎週 `Vol.N 未登録` で落ちます。**
`next_vol` は現在 **11** なので、キーは `"11"` から始めてください。

### 2. cron を戻す

`.github/workflows/weekly_article.yml` の、コメントアウトしてある `schedule:` と `- cron:` の2行（と `#` ）を外すだけです。

### 3. 1回だけ手で回して確かめる

GitHub の Actions から **`workflow_dispatch`（手動実行）** で1回流し、`output/` ができて記事がcommitされることを見てから、週次に任せてください。
※ `workflow_dispatch` は**止めていません**。いつでも手動実行できます。

---

## ⚠️ 触ってはいけないもの

- **`vol_state.json` を消さないこと。** `completed_vols=[1..10]` が「千葉県を出し切った」という記録そのものです。消すと、どこまで出したかが分からなくなります。
